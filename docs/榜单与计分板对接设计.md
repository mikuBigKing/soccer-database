# 榜单 + 计分板对接 设计（本域：赛事门户域 + 运动员端）

> 状态：A/B/C 已实施并验证（2026-11-05），见「九、实施与验证记录」
> 决策记录（2026-11-05）：
> 1. 计分板上报**只更新比分 + 原文留痕**，不自动生成进球事件（进球球员由管理员补录）
> 2. 阶段信息直接加在 `live.Match`：`stage` / `clock_minute` / `score_source`
> 3. 现场网关运行环境：**Windows 工控机**
> 4. 榜单对外入口：**公众端 + 运动员端**

---

## 一、范围

| 功能 | 边界 |
|---|---|
| 选手进球榜 | 按组别聚合 `goal` 事件，输出球员 / 球衣号 / 球队 / 进球数 |
| 分组进球统计 | 每个 `group_type` 的场次、总进球、场均、进球时段分布 |
| 球队进球榜 | 按球队聚合进球 / 失球 |
| 计分板对接 | ESP32 → 本域网关 → 云端；本域负责网关开发、部署、联调 |
| 厂商赛事 | 市州及以上仍走厂商接口，通过同一个 `ScoreboardService` 落同一比分与阶段模型 |
| 异常兜底 | 任一链路失败切人工上传，`score_source=manual` 标记来源 |

不负责：报名、教练端、校级端。

## 二、端到端流程

```
ESP32 计分器（按键/数码管）
   │ UART 115200 8N1，ASCII 行 + CRC32
   ▼
本地网关（Windows 工控机）
   ├─ 串口读取 → CRC 校验（失败计数并丢弃）
   ├─ 用 SQLite(WAL) 队列落盘：pending → sent → acked
   ├─ 断网指数退避重传，恢复后按 seq 顺序补传
   ├─ HMAC-SHA256 签名（device_id + secret）
   ▼
云端 POST /api/device/live/report
   ├─ 设备鉴权（live_devices）
   ├─ seq 幂等 / 回退拦截（live_score_feeds 唯一键）
   ├─ ScoreboardService：比分 + 阶段 + 来源，一次事务落库
   ▼
共用比分与阶段模型
   ├─ 公众端比分、榜单实时刷新（缓存失效）
   ├─ 完场 → 报告 AI 生成
   └─ 异常 → 管理端人工修正（score_source=manual）
```

## 三、数据模型

### 3.1 `live.Match` 新增字段（迁移 `live/0002`，不碰 accounts）

| 字段 | 类型 | 说明 |
|---|---|---|
| `stage` | char(16)，choices | `not_started / first_half / half_time / second_half / extra_time / penalty / finished` |
| `clock_minute` | PositiveSmallIntegerField，默认 0 | 计分板当前比赛时钟（分钟） |
| `score_source` | char(8)，默认 `manual` | `manual / device / vendor`，公众端可展示来源 |

> `status` 与 `stage` 的联动：`first_half/half_time/second_half/extra_time/penalty → live`；`finished → finished`；`not_started → not_started`。人工修改比分时把 `score_source` 置 `manual`。

### 3.2 `live_devices`

| 字段 | 类型 | 说明 |
|---|---|---|
| `device_no` | char(32) unique | 网关编号，如 `GW01` |
| `name` | char(64) | 场地/用途描述 |
| `secret` | char(64) | HMAC 密钥（仅管理员可见，不进日志） |
| `match` | FK `live.Match`，可空 | 默认绑定的比赛；为空时必须报文带 `match_id` |
| `enabled` | bool，默认 True | 停用后拒绝上报 |
| `last_seq` | BigInt，默认 0 | 已接受的最大 seq |
| `last_seen_at` | datetime，可空 | 心跳/最近上报时间 |

### 3.3 `live_score_feeds`（原文留痕，审计与重放）

| 字段 | 类型 | 说明 |
|---|---|---|
| `device` | FK `live_devices` | |
| `match` | FK `live.Match` | |
| `seq` | BigInt | |
| `payload` | JSON | 原始报文（不含签名） |
| `applied` | bool | 是否成功写入比分 |
| `error` | char(200) | 失败原因（幂等/乱序/已结束等） |
| `reported_at` | datetime | 设备上报时间 |

约束：`unique(device, match, seq)`；索引 `(match, -reported_at)`。

## 四、榜单

### 4.1 统计口径

- 只统计 `status=finished` 且未软删的比赛；
- 进球只认 `type=goal`；
- 选手榜优先按 `athlete_id` 聚合；无关联的按 `player_name` 兜底，返回 `has_athlete=false`；
- 出场、助攻等扩展字段本期不做；
- 进球时段桶沿用报告 AI 的 6 段：`0-15 / 16-30 / 31-45 / 46-60 / 61-75 / 76-90`。

### 4.2 公众端接口

```
GET /api/public/live/leaderboards?group_type=middle_school&limit=10
```

| 参数 | 说明 |
|---|---|
| `group_type` | 可选：`university / middle_school / primary_school`，缺省 `all` |
| `limit` | 射手榜条数，默认 10，最大 50 |

响应 `data`：

```json
{
  "group_type": "middle_school",
  "updated_at": "2026-11-05 10:00:00",
  "top_scorers": [
    {"rank": 1, "athlete_id": 101, "name": "王球员", "jersey_no": 10,
     "team_id": 3, "team_name": "成都实验中学足球队", "group_type": "middle_school",
     "goals": 7, "has_athlete": true}
  ],
  "group_goals": [
    {"group_type": "middle_school", "label": "中学组", "matches": 12,
     "goals": 38, "avg_goals": 3.17,
     "goal_buckets": {"0-15": 6, "16-30": 5, "31-45": 6, "46-60": 7, "61-75": 7, "76-90": 7}}
  ],
  "team_goals": [
    {"team_id": 3, "team_name": "成都实验中学足球队", "group_type": "middle_school",
     "matches": 6, "goals": 15, "goals_against": 7}
  ]
}
```

- `group_type=all` 时 `group_goals` 返回三个组别各一行；`team_goals` 返回全部球队；
- 无数据时三个数组返回 `[]`，`code=0`。

### 4.3 运动员端

`GET /api/athlete/standings` 保持现有字段不变，**仅新增**：

```json
{
  "my_rank": {"athlete_id": 101, "goals": 4, "rank": 6},
  "team_goals": [...]
}
```

### 4.4 性能与缓存

- 用 `values().annotate()` 聚合，禁止逐队/逐场循环（现有 `standings()` 是全量循环，本期榜单单独实现，不动老逻辑）；
- 结果进 Django locmem 缓存 60s，key 含 `group_type/limit`；
- 以下写入触发 `leaderboard cache clear`：事件新增/修改/删除、比赛状态改为 finished、比分人工修正。

## 五、计分板云端接口

### 5.1 上报

```
POST /api/device/live/report
Headers:
  X-Device-Id: GW01
  X-Timestamp: 1730800123          # 秒级，±300s 内有效
  X-Nonce: a1b2c3d4                # 8–32 位，5 分钟内不可复用
  X-Sign: <hex lowercase>
Body:
  {"seq":1027,"home_score":2,"away_score":1,"stage":"second_half",
   "clock_minute":67,"reported_at":"2026-11-05T10:00:00+08:00","match_id":23}
```

签名串与算法：

```
sign_str = f"{method}\n{path}\n{timestamp}\n{nonce}\n{sha256(body_bytes)}"
X-Sign   = hmac_sha256(device.secret, sign_str).hexdigest()
```

`match_id` 可省略，默认取 `device.match`；设备已绑定比赛时若报文里的 `match_id` 不一致 → `40001`。

响应 `data`：

```json
{"match_id":23,"seq":1027,"home_score":2,"away_score":1,
 "stage":"second_half","status":"live","ack":"ok"}
```

### 5.2 校验与错误码

| 规则 | 错误码 |
|---|---|
| 设备不存在 / 停用 / 签名错误 | `20004` |
| 时间戳过期 / nonce 复用 | `20004`（文案「请求已过期」） |
| seq 已处理过（`== last_seq` 或已存在记录） | `40009` |
| seq < `last_seq`（乱序/回退） | `40004`（新增码：报文序号乱序） |
| 比分回退（新值小于当前比分） | `40001`（文案「比分不可回退，请人工修正」） |
| 比赛已 `finished` | `40002` |
| 比赛不存在 / 不属于设备 | `30001` |
| `stage` 非法枚举 | `10001` |

> 允许 seq 跳号（网关断网期间丢帧），只要求单调递增。

### 5.3 落库逻辑（`ScoreboardService.apply`）

```
transaction.atomic():
  match = Match.select_for_update()
  if match.status == finished: 40002
  if seq <= device.last_seq: 40009 / 40004
  if home_score < match.home_score or away_score < match.away_score: 40001
  写 live_score_feeds(applied=True)
  match.home_score/away_score/stage/clock_minute/score_source='device'
  match.status = 由 stage 映射
  match.version += 1
  device.last_seq = seq; device.last_seen_at = now
  若 stage=finished: 榜单缓存失效 + 触发报告生成（可选开关）
```

任何校验失败也写一条 `applied=False` 的 `live_score_feeds`（便于现场排查，用 `transaction.atomic` 包裹后独立提交）。

### 5.4 异常兜底：人工补报

```
POST /api/admin/live/matches/{id}/score        # 权限 live:match:update
Body: {"home_score":2,"away_score":1,"stage":"second_half","clock_minute":70,"version":9}
```

- 用途：网关 / 厂商接口异常时由赛事管理员手工上传比分，落库后 `score_source=manual`；
- 允许比分修正回退（设备侧仍拒绝回退，裁判改判只走人工）；
- `stage`/`clock_minute` 可选；带 `stage=finished` 时联动 `status=finished` 并失效榜单缓存；
- 已完场（`status=finished`）返回 `40002`，防止赛中数据被事后改写；
- 乐观锁：`version` 不匹配返回 `code=9`。

## 六、本地网关（Windows）

### 6.1 目录

```
gateway/
├─ main.py            # 入口：串口线程 + 上传线程 + 心跳 + 信号处理
├─ config.py          # YAML 读取与校验
├─ serial_reader.py   # 串口读取、帧解析、CRC32
├─ queue_store.py     # SQLite 队列（WAL），pending/sent/acked
├─ cloud_client.py    # HMAC 签名 + 上报 + 错误分类
├─ mock_serial.py     # 无硬件模拟器（按时间线灌报文）
├─ config.yaml
└─ tests/test_protocol.py
```

### 6.2 串口帧

```
{"v":1,"dev":"GW01","seq":1027,"h":2,"a":1,"st":"2H","clk":67,"ts":1730800000}*<CRC32>\r\n
```

- CRC32 覆盖 `{` 到 `}` 的字节，十六进制 8 位；
- `st` 缩写映射：`NS → not_started / 1H → first_half / HT → half_time / 2H → second_half / ET → extra_time / PK → penalty / FT → finished`；
- 解析失败：丢弃 + 计数 + 日志（限速，避免刷屏）。

### 6.3 队列与重传

| 状态 | 含义 |
|---|---|
| `pending` | 已落盘，待上传 |
| `sent` | 已发出，等待响应 |
| `acked` | 云端返回 `0` 或 `40009`（幂等视为成功） |

- 退避：1s → 2s → 4s … 上限 60s，成功后重置；
- 401/403（`20004`）：停止重试并告警（密钥问题，重试无意义）；
- 40002（比赛已结束）：标记 `dead`，保留现场数据；
- 进程重启后从 `pending/sent` 继续，保证断电不丢。

### 6.4 部署（Windows 工控机）

- 任务计划程序「开机启动」运行 `pythonw gateway/main.py`，或 NSSM 注册为服务；
- `config.yaml` 现场灌装：COM 口、波特率、`device_no`、`secret`、`match_id`、云端地址；
- 日志 `gateway/logs/gateway.log` 按天切割，保留 30 天；
- 断网演练：拔网 30 分钟 → 队列积压 → 恢复后按 seq 补传，云端不得重复计分。

### 6.5 现场联调清单

1. 设备号 / 密钥与云端 `live_devices` 一致；
2. 串口 COM 口与波特率匹配，CRC 校验通过率 100%；
3. 按键 +1 后 3 秒内云端比分变化，`score_source=device`；
4. 断网 10 分钟再恢复，比分最终一致且无重复；
5. 重复报同一 seq 返回 `40009` 且比分不变；
6. 比赛结束后上报返回 `40002`，网关进入 dead 并告警；
7. 人工修正比分后 `score_source` 变 `manual`。

### 9.2 验证结果

- 后端冒烟：**97 项通过 / 0 失败**（含榜单 9 项、计分板 13 项；原 74 项无回归）。
- 网关单测：`python -m unittest gateway.tests.test_protocol` **26 项通过**。
- 网关 → 云端真实联调（本机 8000 端口）：
  1. 模拟 9 帧 `NS→1H→HT→2H→FT`（比分 0-0 → 2-2）逐帧上传，全部 `code=0`；云端最终 `2-2 / finished / clock=90 / score_source=device`，`live_score_feeds` 9 条全部 `applied=True`，`device.last_seq=9`。
  2. 完场后再发 `seq=10`（3-2）→ 云端 `40002`，网关标记 `dead` 并打 ERROR 日志，不再重试。
  3. 断网演练：目标地址改 `127.0.0.1:9` 上传 9 帧 → 全部保留 `pending`，首帧 `attempts=1` 并写入退避 `next_at`；恢复云端后按 seq 顺序补传，9 帧全部返回 `40009`（幂等），比分未重复累加。

> 现场三项仍需在工控机 + 真实 ESP32 上完成：COM 口/波特率匹配、CRC 通过率 100%、按键 +1 后 3 秒内云端可见（见 6.5 清单）。
