# 管理端与遴选接口契约（新增部分）

统一响应：`{"code":0,"msg":"","data":...,"trace_id":"..."}`，`code != 0` 即失败。
鉴权：`Authorization: Bearer <access_token>`；除 `/api/portal/*` 外均为管理员专属（role=admin）。

## 1. 管理员账号管理 `/api/admin/users`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/users` | 列表 |
| POST | `/api/admin/users` | 创建任意角色账号 |
| GET | `/api/admin/users/{id}` | 详情 |
| PUT | `/api/admin/users/{id}` | 修改姓名/手机/邮箱/状态/数据范围 |
| DELETE | `/api/admin/users/{id}` | 禁用（软删，不物理删除） |
| POST | `/api/admin/users/{id}/reset-password` | 重置密码 |
| POST | `/api/admin/users/batch-reset-password` | 批量重置 |

列表参数：`role`（可逗号分隔）、`status`、`keyword`（姓名/手机/邮箱）、`province_id`、`city_id`、`school_id`、`page`、`page_size`。

创建体：

```json
{
  "role": "city",
  "name": "成都市管理员",
  "phone": "13800000000",
  "password": "可选，缺省用 DEFAULT_RESET_PASSWORD",
  "province_id": 1,
  "city_id": 2,
  "school_id": 3,
  "county": "武侯区"
}
```

角色与必填：`admin` 必填 `email`；其余角色必填 `phone`；`province` 必填 `province_id`；`city`/`county` 必填 `city_id`；`school` 必填 `school_id`。

返回项：`id/name/role/role_label/phone/email/status/status_label/last_login/created_at` + 范围字段。

## 2. 参赛管理 `/api/admin/teams`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/teams` | 列表（`city_id`/`county`/`school_id`/`group_type`/`status`/`competition_id`/`keyword`） |
| GET | `/api/admin/teams/{id}` | 详情：学校、教练、报名记录、成员数 |
| GET | `/api/admin/teams/{id}/athletes` | 成员列表（含证件资格、公示状态） |
| GET | `/api/admin/teams/{id}/coaches` | 教练信息（含审核状态） |
| GET | `/api/admin/teams/{id}/matches` | 比赛记录（比分、结果 win/draw/loss） |
| POST | `/api/admin/teams/{id}/reset-coach-password` | 重置球队教练账号，body 可传 `password` |

数据范围：admin 全量；city 仅本市；school 仅本校，越权返回 403。

## 3. 全局审计 `/api/admin/audit-logs`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/audit-logs` | 查询分页 |
| GET | `/api/admin/audit-logs/export` | 导出 CSV（最多 1 万条，UTF-8 BOM） |

参数：`module`、`action`（模糊）、`resource_type`、`resource_id`、`actor_id`、`actor_role`、`keyword`、`date_from`、`date_to`（YYYY-MM-DD）。

记录字段：`id/created_at/actor_id/actor_name/actor_role/module/action/resource_type/resource_id/ip/trace_id/before/after`。

写入规则：业务层通过 `apps.common.audit.write_audit()` 记录明细；中间件对未显式记录的写请求兜底一条 HTTP 级审计（`resource_type=http`）。

## 4. 遴选档案 `/api/admin/selection/profiles`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/selection/profiles` | `competition_id`/`group_type`/`team_id`/`status`/`id_card`/`keyword` |
| POST | `/api/admin/selection/profiles` | `{competition_id, group_type?, team_id?}` 从报名单导入（跳过草稿） |

返回项：`id/competition_id/athlete_id/name/id_card/team_id/team_name/group_type/status/initial_total/final_total/created_at`。

## 5. 评分 `/api/admin/selection/scores`

权重：进球 25%、防守 25%、助攻 20%、犯规 30%，每项 0–100，总分保留两位小数。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/selection/scores` | `competition_id`/`group_type`/`team_id`/`stage`（initial/final） |
| POST | `/api/admin/selection/scores` | 新增或覆盖同一档案同一阶段 |
| PUT | `/api/admin/selection/scores/{id}` | 修改（未传的维度沿用原值并重算总分） |
| GET | `/api/admin/selection/scores/summary` | 总人数/均分/最高/最低 + 按球队汇总 |
| GET | `/api/admin/selection/scores/export` | 导出 xlsx |

写入体：

```json
{
  "profile_id": 10,
  "stage": "final",
  "goals_score": 85,
  "defense_score": 70,
  "assist_score": 60,
  "foul_score": 90,
  "remark": "复选第二场"
}
```

## 6. 最佳球员 `/api/admin/selection/best`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/selection/best/generate` | `{competition_id, group_type, top_n=11}`，按复选总分排序生成 |
| GET | `/api/admin/selection/best` | `competition_id`/`group_type`/`published` |
| POST | `/api/admin/selection/best/publish` | `{competition_id, group_type, published=true}` 发布/取消发布 |

排序：复选总分降序，同分比进球评分，再按档案 id。重复生成会覆盖该组别未发布结果。

## 7. 前台 `/api/portal/`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/portal/selection-scores/` | 登录用户可看评分列表（参数同上） |
| GET | `/api/portal/selection-best/` | 仅返回已发布结果 |

返回结构与后台上表一致，前端 `api/selection.ts` 可直接替换为这两个地址。

## 8. 数据规则

- 球衣号：**同队唯一、跨队可重复**；已软删球员不占用号码（数据库条件唯一索引 `uniq_athlete_team_jersey`）
- 身份证：**全局唯一**，球员与教练各自独立校验；已软删档案不占用（`uniq_athlete_id_card` / `uniq_coach_id_card`），应用层同时给出中文错误提示
- 身份证检索：列表的 `id_card` 参数按**后四位**匹配（`id_card=002X`），也兼容传完整 18 位；球员、教练、遴选档案、停赛/换队查询均生效；`keyword` 模糊搜索同样可命中证件号片段
