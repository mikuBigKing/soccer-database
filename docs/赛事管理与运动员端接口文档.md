# 赛事管理（直播）与运动员端 接口文档

- 后端：Django 6.1 + DRF 3.18（`d:\ball\soccer-django`），Base URL：`http://127.0.0.1:8000/api`
- 原 Laravel 版实现保留在 `d:\ball\soccer-database\backend`（仅作对照，已不再运行）
- 统一响应：`{"code":0,"msg":"success","data":{},"success":true,"trace_id":"xxx"}`
- 认证：`Authorization: Bearer {token}`（JWT，登录返回 `token`/`access` 同值 + `refresh`）
- 日期时间：`Y-m-d H:i:s`（如 `2026-10-26 15:00:00`），对齐前端契约
- 枚举中文名统一用 `*_label` 字段返回：`group_type_label`、`status_label`、`type_label`、`role_label`
- 列表统一返回 `{list, next_page, total, page, page_size}`；`next_page` 为 `null` 表示末页
- 前端契约以 `docs/前端契约-live.ts` 为准

## 响应码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 10001 | 参数校验失败 |
| 10006 | 不支持的文件格式 |
| 10007 | 文件大小超出限制（≤10MB） |
| 20001 | 未登录或登录已过期 |
| 20002 | 账号或密码错误 |
| 20003 | 账号已被禁用 |
| 20004 | 无操作权限 |
| 30001 | 资源不存在 |
| 9 | 乐观锁冲突（数据已被他人修改） |
| 40002 | 比赛已结束，禁止修改 |
| 40009 | 重复提交（幂等拦截） |
| 50008 | 人脸核验服务异常 |
| 60001 | 数据存储异常 |
| 90001 | 系统繁忙 |

# 一、认证（共享）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | /api/health | 免登 | 健康检查 `{status:"up", time}` |
| POST | /api/auth/register | 免登 | 自助注册（personal / coach / athlete） |
| POST | /api/auth/login | 免登 | 非管理员统一登录（手机号 + 密码） |
| POST | /api/admin/auth/login | 免登 | 管理员独立登录（邮箱 + 密码，仅 role=admin） |
| POST | /api/auth/logout | 登录 | 登出（传 `refresh` 则加入黑名单） |
| GET | /api/auth/me | 登录 | 当前用户 + profile 概要 |

**register 入参**：`name`(≤50)、`phone`(11 位手机号, unique)、`password`(≥6)、`role`(personal|coach|athlete)
- 运动员/教练注册后 profile `status=pending`，待校级审核。

**login 入参**：`phone`、`password`
**admin login 入参**：`email`、`password`

**登录返回 data**：
```json
{
  "token": "xxx",
  "user": { "id": 1, "name": "王球员", "role": "athlete", "status": "active",
            "profile": { "team_id": 1, "jersey_no": 9, "status": "approved" } }
}
```

角色枚举：`admin / province / city / school / coach / athlete / personal`
账号状态：`active / disabled`；profile 审核态：`pending / approved / rejected`

# 三、赛事直播 — 管理端

- 前缀 `/api/admin/live`，鉴权：`auth:sanctum` + `permission:live:*`（管理员独立登录后获得）

## 3.1 比赛 CRUD 与状态流转

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /matches | live:match:view | 列表 |
| POST | /matches | live:match:create | 创建 |
| GET | /matches/{id} | live:match:view | 详情 |
| PUT | /matches/{id} | live:match:update | 更新（乐观锁，需带 version） |
| DELETE | /matches/{id} | live:match:delete | 删除 |
| PATCH | /matches/{id}/status | live:match:update | 状态流转 |
| PUT | /matches/{id}/lineup | live:match:update | 更新阵容（乐观锁） |

**创建比赛入参**：`group_type`*(必填)、`home_team_name`*(必填)、`away_team_name`*(必填)、`home_team_logo`、`away_team_logo`、`match_time`*(必填,date)、`venue`

**更新比赛入参**：`version`*(必填) + 上述字段（sometimes）

**状态流转入参**：`action`(start|finish)、`version`(必填)
- `not_started → live → finished`，finished 后锁定，修改返回 40002。

**阵容入参**：`version`、`lineup_home[]`、`lineup_away[]`，球员项：`name`、`no`、`position`、`is_captain`

## 3.2 比赛事件（goal 联动比分）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /matches/{id}/events | live:event:manage | 事件列表（可选 `since_id` 增量拉取） |
| POST | /matches/{id}/events | live:event:manage | 新增事件 |
| PUT | /events/{id} | live:event:manage | 修改事件 |
| DELETE | /events/{id} | live:event:manage | 删除事件 |

**新增事件入参**：
- `type`*(goal|yellow|red|substitution|text)
- `minute`*(0-130)
- `team_side`(home|away，除 text 外必填)
- `player_name`（除 text 外必填）、`player_no`(0-99)
- `related_player_name`（换人时必填=换上球员）
- `content`（text 类型必填 ≤500）
- `client_token`*(≤64，幂等键；重复提交返回 40009)
- 可选 `athlete_id`（关联运动员档案，供运动员端聚合）

**事件增/改/删统一返回**（前端 `EventActionResult`）：

```json
{ "event": { "id": 1, "type": "goal", "type_label": "进球", "minute": 12,
             "team_side": "home", "player_name": "王球员", "player_no": 10,
             "related_player_name": null, "content": null, "created_at": "2026-10-23 18:30:00" },
  "home_score": 1, "away_score": 0, "version": 3 }
```
删除时 `event` 为 `null`，比分与 version 仍返回最新值。

事件类型 goal 新增/删除自动增减对应方比分（事务内），并同步 `version+1`。

## 3.3 裁判配置

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /matches/{id}/referees | live:referee:manage | 裁判列表 |
| PUT | /matches/{id}/referees | live:referee:manage | 整体替换 |

入参：`referees[]`（≤4 人），每项 `role`(chief|assistant|fourth)、`name`；chief/fourth ≤1、assistant ≤2。

## 3.4 赛事文件

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /matches/{id}/files | live:file:manage | 文件列表 |
| POST | /matches/{id}/files | live:file:manage | 上传（multipart） |
| GET | /files/{id}/download | live:file:manage | 下载（私有 disk 鉴权） |
| DELETE | /files/{id} | live:file:manage | 删除 |

上传入参：`type`(sign_in|record_confirm|referee_report)、`file`(pdf/jpg/jpeg/png ≤10MB)；格式错误 10006、超限 10007。

文件项字段：`id`、`match_id`、`type`、`file_name`、`file_path`、`mime`、`size`、`uploaded_by`、`created_at`。

## 3.5 直播链接

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| PUT | /matches/{id}/live-link | live:link:manage | 设置/清空直播链接 |

入参：`live_link`（URL ≤512，可置空清空）。

**返回**：`{"live_link": "https://...", "version": 4}`，`version` 自增，前端需同步本地版本号。

## 3.6 人脸核验（mock driver）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | /matches/{id}/face-verify | live:face:manage | 发起核验 |
| GET | /matches/{id}/face-verify-records | live:face:manage | 核验记录 |

入参：`player_name`*(必填)、`player_no`、`photo`*(jpg/jpeg/png ≤10MB)；外部服务超时/失败返回 50008。

记录字段：`id`、`match_id`、`player_name`、`player_no`、`photo_path`、`result`、`score`(字符串)、`channel`、`request_id`、`remark`、`created_by`、`created_at`。

# 四、运动员端

- 前缀 `/api/athlete`，鉴权：`Authorization: Bearer` + `role:athlete`
- 前置：运动员注册并审核通过（profile.status=approved）且已挂靠球队（team_id）后，matches/stats/standings 才有数据。

## 4.1 个人资料

**GET /api/athlete/profile**

```json
{
  "id": 1, "name": "王球员", "jersey_no": 10, "position": "中场",
  "status": "approved", "reject_reason": null,
  "team": { "id": 1, "name": "成都实验中学足球队", "logo": null,
            "group_type": "middle_school", "status": "approved" }
}
```

**PUT /api/athlete/profile**（FormRequest：ProfileUpdateRequest）

| 字段 | 规则 |
|---|---|
| name | string ≤50 |
| jersey_no | int 0-99 |
| position | string ≤20 |

三项均 `sometimes`，传啥改啥；改 name 会同步 users.name。返回更新后的 profile（结构同 GET）。

## 4.2 我的比赛

**GET /api/athlete/matches**（可选 `?status=not_started|live|finished`）

按我所属球队查询（主队或客队身份均可命中）：

```json
{
  "list": [
    { "id": 3, "group_type": "middle_school", "match_time": "2026-10-26 15:00:00",
      "venue": "成都体育中心", "status": "not_started", "is_home": true,
      "opponent": "绵阳南山中学", "my_score": 0, "opponent_score": 0,
      "live_link": null }
  ],
  "team_id": 1
}
```
`is_home` 标识我方主客队身份；`my_score/opponent_score` 已按我方视角换算。

## 4.3 我的数据统计

**GET /api/athlete/stats**

```json
{
  "goals": 2, "assists": 0, "yellow_cards": 1, "red_cards": 0,
  "appearances": 2,
  "team_record": { "win": 1, "draw": 1, "loss": 0 }
}
```
- 数据来源：`match_events` 按 `athlete_id` 实时聚合（不维护冗余统计表）。
- `appearances` = 参与过事件的已结束比赛数。
- `team_record` = 所属球队已结束比赛的胜/平/负。

## 4.4 积分榜 / 射手榜

**GET /api/athlete/standings**（按我所属球队的组别）

```json
{
  "group_type": "middle_school",
  "standings": [
    { "team_id": 1, "team_name": "成都实验中学足球队", "played": 2,
      "win": 1, "draw": 1, "loss": 0, "gf": 3, "ga": 2, "gd": 1,
      "points": 4, "is_my_team": true }
  ],
  "top_scorers": [
    { "athlete_id": 1, "name": "王球员", "jersey_no": 10,
      "team_name": "成都实验中学足球队", "goals": 2 }
  ]
}
```
- 积分：胜 3 平 1 负 0；排序：积分 → 净胜球 → 进球数。
- 仅统计该组别已结束且双方均绑定 team_id 的比赛；射手榜取前 10。

# 五、数据模型关键字段

**matches**：group_type、home/away_team_name、home/away_team_id(FK→teams, 可空)、match_time、venue、status、home/away_score、lineup_home/away(JSON)、live_link、version(乐观锁)

**match_events**：match_id、type、minute、team_side、athlete_id(FK→athlete_profiles, 可空)、player_name、player_no、related_player_name、content、client_token(唯一, 幂等)

**athlete_profiles**：user_id、team_id(FK)、name、jersey_no、position、status(pending/approved/rejected)、reject_reason

**users**：phone(unique)、role、status(active/disabled)、email(管理员用)
