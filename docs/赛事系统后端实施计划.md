# 赛事系统后端实施计划（新闻 + 运动员端 + 多角色体系）

> 备份日期：2026-10-23。范围：赛事新闻首页、运动员端、7 角色账号体系、赛事与球队体系。赛事直播模块已完成（见 MAPPING.md）。

## 一、整体架构

```
认证：Sanctum + users 主表（role 字段）+ 各角色 profile 表
统一登录：POST /api/auth/login（除管理员外共用）
管理员登录：POST /api/admin/auth/login（独立）
权限：middleware 按 role + 数据范围（省/市/校）隔离
日志：校级以上写操作 → audit_logs 表（独立于现有三通道日志）
```

## 二、已确认的设计决策

1. 账号方案：方案 C（users 主表 + 各角色 profile 表）
2. 登录：管理员独立登录页，其余 6 种统一登录页
3. 注册：个人/运动员/教练自助注册；校级/市级/省级/管理员由管理员创建
4. 运动员与教练由校级审核；注册为教练审核通过后才能创建球队
5. 省/市数据预置四川省
6. 同意改造现有 matches 表
7. 比赛归属于赛事，由省级或管理员管理
8. 校级以上操作均计入审计日志（各级别分别记录）

## 三、数据表设计

| 表 | 核心字段 | 说明 |
|---|---|---|
| `users`（改造现有） | id, phone(唯一), password, role(admin/province/city/school/coach/athlete/personal), status(active/disabled), timestamps | 主表，现有 users 表扩展 role/status |

| `athlete_profiles` | user_id, team_id, name, jersey_no, position, status(pending/approved/rejected) | 运动员 |

### 3.4 新闻（赛事门户）

## 四、7 种账号功能边界

### 1. 管理员账号（admin，超管）
- 所有角色的账号管理（创建/禁用/重置密码）
- 系统配置（字典、日志查看）
- 全量数据查阅与修改
- 操作审计日志查看

### 2. 省级账号（province）
- **发布赛事**（标题、详情、规章制度、组别、报名时间）
- 审核全省球队报名
- 全省赛事/比赛/球队/运动员数据查阅
- 全省统计报表（积分榜、射手榜、参赛统计）
- 发布省级新闻/公告

### 3. 市级账号（city）
- 本市范围内数据查阅
- 审核本市学校/球队注册
- 本市赛事承办编排
- 本市统计报表
- 发布市级公告

### 4. 校级账号（school）
- 本校球队/运动员审核
- 本校数据查阅与统计
- 管理本校信息（名称、Logo、简介）
- 发布校级通知

### 5. 教练账号（coach）
- 创建球队、编辑球队信息
- **申报比赛**（为球队报名赛事）
- 管理本队运动员（邀请/移出）
- 查看本队比赛赛程、数据
- 查看本队统计

### 6. 运动员账号（athlete）
- 个人资料维护
- 查看我的比赛、我的数据（进球/出场/红黄牌）
- 报名参赛
- 查看赛事公告、积分榜

### 7. 个人账号（personal，基础账号）
- 浏览赛事概览（赛程、积分榜、射手榜）
- 观看比赛直播（已有）
- 查看新闻（待开发）
- 可升级为运动员或教练（填写资料 + 身份认证）

## 七、关键约束（沿用项目规范）

- 分层架构：Controller → Service → Model，禁止跨层
- 事务在 Service，事务内禁第三方 IO
- 统一响应五字段 + trace_id
- 响应码：40002 状态不可操作、9 乐观锁、40009 幂等、20001 未登录
- 校级以上写操作必须写 audit_logs
- 数据范围隔离：省级看全省、市级看本市、校级看本校、教练看本队、运动员看个人
